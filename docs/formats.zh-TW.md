# 資源格式與更新方式

[English](formats.md) | 繁體中文（台灣）

工具支援的格式是遊戲內部資源。僅憑副檔名，無法判定資料配置是否相容。
若檔頭、邊界或內容不符預期，工具會在寫入輸出前拒絕處理。

## 文字資料檔

記錄前方是大端序（big-endian）偏移量表，第一個偏移量同時表示表格長度。
偏移量必須嚴格遞增，且指向檔案範圍內。使用 CLI 時，必須明確指定偏移量寬度
與記錄類型。

訊息與劇情記錄包含一個以 NUL 結尾的 CP932 字串，後方以零填補。選單記錄以
兩個位元組開頭，分別宣告字串寬度與字串數量，接著是對應數量的 NUL 結尾字串
與零填補。不明的非零資料不會被默默丟棄。

匯出的 JSON 保留記錄身分與輸入來源的摘要值。請只編輯 `texts` 陣列。
匯入時會重新解析原始來源，確認其仍與匯出時一致，檢查字串數量與已知控制符號，
再將各筆編修記錄放入原本配置的空間，不移動偏移量。

無法編碼的字元會被視為錯誤。初版工具集沒有字元替換對照表或字型產生流程。
更完整的中文化流程需要另外準備這些輸入，並確認適用的字型授權。

## 影格集合

大端序四位元組偏移量表指向各個影格。每個影格包含尺寸、小型字典，以及按列壓縮的
四位元平面像素資料。目前編解碼器接受的尺寸上限為 640 × 400。
使用目前的編碼器修改影格時，寬度必須能被 4 整除。

BMP 交換會保留 0–15 的色彩索引。灰階色盤由數學運算產生，並非遊戲色盤。
匯入器接受未壓縮的 8 位元 Windows BMP，其資訊標頭須為 40 位元組，並保留匯出時
使用的 256 色色盤。圖片編輯器必須保留這個格式與色盤順序。

未修改的影格會保留原始編碼位元組。修改後的影格會重新編碼，並精確占用原有空間；
若編碼器無法放入或填滿該空間，更新就會失敗。影格偏移量、尺寸旗標與其他影格
都會保留。手動編輯區域之外的像素，由編輯者自行確認；工具會保留其他影格，
但不會自行推定選取影格中的文字區域。

## 內部封存檔

LW11 使用具名項目；LS10 與 LS11 使用索引項目。其標頭包含 256 位元組的
字面值字典，以及記錄壓縮長度、解壓後長度與偏移量的目錄。
壓縮項目使用 Wyle 編碼的 LZSS 串流。LW11 也支援未壓縮項目，
以壓縮長度等於解壓後長度表示。本工具的壓縮處理屬於檔案格式操作，
未實作金鑰輸入或外層套件解密。

工具會檢查目錄的邊界、順序與重疊情形。封存內名稱僅作為中繼資料顯示，
不會用來組合輸出路徑。使用者須依索引選取項目，並自行指定輸出路徑。

替換資料的解壓後長度必須保持不變，編碼後也必須放得進原本的壓縮配置空間。
工具只更新該項目的壓縮長度欄位與資料內容，不變動未被引用的尾端位元組，
因此檔案總長及其他項目的偏移量都會維持不變。
寫入前會再次解碼，驗證所選項目的結果。

## 驗證範圍

格式驗證與讀回比對成功，表示工具完成了所描述的資源操作；這不代表修改後文字
一定能放入遊戲視窗、字型一定含有所需字形，或特定遊戲流程一定能正常執行。
本專案提供的是資源編輯工具，並非遊戲安裝器。
